# 검토와 검증 결과

검증일: 2026-09-17

## 기능 구현

- 실제 SVG 사람 캐릭터와 책상·모니터·의자, 가구 편집, 좌석 배정.
- 아이디·비밀번호 회원가입/로그인, 필수 이름·직책 설정, 프로필·비밀번호 변경, 로그아웃.
- 로그인한 본인의 한국 날짜 기준 출퇴근과 계정별 권한.
- 여러 배치도·테마 저장, 선택 유지, 공동 변경 갱신, 초안 보호.
- 공유 달력의 업무 유형, 최초 등록자 표시, 내 일정/팀원별 필터.
- 사무실 4개·야외 마당·카페, 방향키/WASD·화면 방향 버튼, 가구·건물 충돌, 출입구 클릭/E 이동.
- 본인 자리 예약·앉기·일어나기, 타인 예약 보호, 캐릭터·책상 상태 메시지.
- 상단 일정 확인 버튼과 큰 달력, 닫기 후 필터 유지 및 중첩 편집창 초점 복귀.

## 전체 코드 검토에서 고친 기존 오류

1. 월 메모 입력 직후 월/과업을 옮기면 예약된 저장이 취소되던 문제. 전환 시 저장을 시작하고 같은 월 저장 순서를 보장합니다.
2. 파일 이력 담당자를 비울 때 DB의 필수 컬럼에 `null`을 보내던 문제. 빈 문자열로 저장합니다.
3. 이력 저장 실패에도 화면 목록에 성공한 것처럼 남던 문제. 서버 성공 후 반영하고 텍스트 실패는 초안을 유지해 다시 저장할 수 있습니다.
4. 휴지통에서 복구한 일정이 열린 과업 달력에 바로 나타나지 않던 문제.
5. 부서 일정 삭제 후 달을 바꿔 삭제 취소하면 이전 달을 다시 읽어 로딩이 남던 문제.
6. 기존 공유 모드 SQL을 재실행할 때 이미 존재하는 `file_logs_open` 정책으로 실패하던 문제.

브라우저 검증:

- `account-browser.cjs`: 가입·필수 내 설정, 저장 실패/재시도, 새로고침 유지, 프로필·비밀번호 변경, 로그아웃/재로그인, 만료된 세션, 모바일, 브라우저 인증 토큰 미보관.
- `department-dashboard.cjs`: 일정 CRUD/복원, 월 이동 후 삭제 취소, 업무 유형/등록자/복합 필터, 기존 작성자 보존, 충돌·실패·미설치, 연도 경계, 모바일.
- `team-workspace.cjs`: 회원가입과 프로필 저장, 출퇴근 및 실패, 자정 경계, 착석 캐릭터, 포인터/키보드 이동, 여러 배치도·테마·회전·삭제, 중복 좌석 방지, 초안 보호/충돌, 모바일.
- `project-workspace.cjs`: 담당자 비우기, 이력 실패 초안·재시도·체크박스 보존, 월 메모 전환/로딩/저장 순서/재시도, 휴지통 일정 즉시 반영.
- `game-world.cjs`: 방향키·화면 방향 버튼의 키보드 누름/해제, 입력·달력 중 이동 차단, 자리 예약 실패/재시도·앉기/해제, 걷기 중 예약 보존, 여섯 공간 출입구·E 이동, 상태 유지, 모바일 너비와 정보 영역 가독성.

서버와 배포 호환성 검사에서 Next.js가 로컬 IP를 `localhost`로 바꿔 정상 요청도 Origin 검사에 걸리는 문제를 수정했습니다. 실제 Host를 기준으로 확인하며 다른 출처의 변경 요청은 계속 차단합니다. 운영 설치에 과거 초대 함수가 없는 경우도 통합 SQL을 실행할 수 있도록 존재 여부를 확인하며, 같은 조건의 DB 회귀 검사를 통과했습니다.

## 정리한 폴더

- 팀 코드는 `src/components/team/`, `src/lib/team/`으로, 계정 UI와 검증 타입은 `src/components/account/`, `src/lib/account/`으로 묶었습니다.
- 사용하지 않는 공용 비밀번호 화면과 직접 팀원 등록 함수를 제거했습니다.
- 구현 계획·구조 설명·이 문서는 `docs/`에, 실행 스크립트는 `scripts/`에 모았습니다.
- 테스트 의존성을 프로젝트 개발 의존성으로 고정해 설치할 수 있게 했습니다.
- 이전 상위 폴더의 `.next`, 임시 테스트 도구 두 폴더, 미사용 시작용 SVG는 `artifacts/archive/`에 보관했습니다. 현재 빌드와 린트는 보관 폴더를 제외합니다.

## 적용 범위

운영 Supabase 데이터는 자동 테스트로 수정하지 않았습니다. 브라우저는 모의 API, DB 검사는 로컬 메모리 PostgreSQL을 사용했습니다. 2026-09-17 사용자가 운영 SQL을 직접 적용한 뒤 계정 준비와 익명 접근 차단을 읽기 전용 검사로 확인했습니다. 적용 절차와 확인 명령은 `docs/deployment.md`에 있습니다.

새 사무실 월드의 운영 SQL 적용·배포는 아직 확인되지 않았습니다. 계정 설치가 완료된 DB에는 `artifacts/setup/teams-office-world-upgrade.sql` 전체를 수동 적용한 다음 이번 앱을 배포합니다. 위치는 실시간 소켓 대신 약 1초 저장·3초 조회를 사용합니다. PGlite는 단일 연결이므로 두 DB 세션의 동시 실행 부하 검사는 포함하지 않습니다.

아이디로 로그인한 팀원이 함께 과업·일정·사무실을 편집합니다. 프로필·출퇴근 변경은 본인만 가능합니다. 출퇴근은 한국 날짜당 한 번이며, 최초 등록자 표시는 부서 공유 달력에 적용합니다. 과업별 포스트잇 일정 구조와 폴더의 개별 복구 방식은 유지합니다. 운영 적용 절차는 `docs/deployment.md`에 정리했습니다.
