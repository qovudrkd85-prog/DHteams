# 우리 사무실 · 마당 · 카페

## 사용법

1. 아이디로 로그인하고 내 이름·직책을 설정합니다.
2. 사무실 화면을 클릭한 뒤 방향키로 캐릭터를 움직입니다. 입력창이나 달력이 열려 있을 때는 이동하지 않습니다.
3. 공간 버튼이나 출입구로 사무실 1~4, 야외 마당, 카페를 오갑니다.
4. 빈 책상을 눌러 **내 자리로 선택**합니다. **자리에 앉기**와 **일어나기**로 자세를 바꿉니다. 걸어 나와도 자리 예약은 유지하며, 자리 해제로 예약을 비웁니다.
5. 팀원 패널에서 60자 이내 상태 메시지를 저장합니다. 빈 내용으로 저장하면 지워집니다.
6. **일정 확인하기**에서 공유 달력을 엽니다. 출퇴근 기록은 기존과 같이 한국 날짜 기준 하루 한 번입니다.

가구 이동·회전·테마·공간 크기는 함께 편집합니다. 자리 예약과 상태·이동 위치는 본인만 변경합니다. 다른 팀원 자리의 가구를 옮길 수 있지만 배정을 바꾸거나 그 책상을 삭제할 수 없습니다. 자리 예약은 배치도별로 관리하며, 방 이동이 다른 방 예약을 해제하지 않습니다.

## 운영 DB 수동 업데이트

**코드 수정만으로 운영 데이터베이스가 갱신되지 않습니다. 새 SQL 적용 성공을 확인한 후 앱을 배포해야 합니다.**

```powershell
npm run db:prepare
```

| 현재 설치 상태 | SQL Editor에서 전체 실행할 파일 |
| --- | --- |
| 개인 계정까지 사용 중 | `artifacts/setup/teams-office-world-upgrade.sql` |
| 이전 공유 모드·팀 공간에서 전체 업데이트 | `artifacts/setup/teams-account-upgrade.sql` |

생성 명령은 로컬 파일만 씁니다. 사용자가 Supabase SQL Editor에서 선택한 파일 전체를 수동 실행합니다. 오류가 나면 트랜잭션 전체가 취소되므로 오류 내용을 확인한 후 수정된 전체 파일로 재시도합니다.

원본 적용 순서는 **팀 공간 → 계정 → 사무실 월드**입니다. `schema-office-presence.sql`이 마지막입니다. 기존 SQL 일부만 재실행하면 이전 권한이나 좌표 제한이 복구될 수 있으므로 전체 통합 파일로 재적용합니다. 새 DB의 기본 테이블 설치는 [Supabase 설치 순서](../supabase/README.md)를 참고하세요.

## 보존되는 데이터

- 가장 오래된 기존 사무실을 `office-1`로 연결하고 이름·가구·좌석·크기를 유지합니다.
- 없는 기본 방만 추가합니다. 새 사무실은 1600×900, 마당은 2200×1100, 카페는 1600×900입니다. 공간은 최대 2400×1200까지 설정할 수 있습니다.
- SQL을 다시 실행해도 꾸민 방을 덮어쓰거나 같은 기본 방을 중복 생성하지 않습니다.
- 기존 이름 전용 팀원과 자리 배정은 보존합니다. 새 계정에 자동으로 연결하지 않습니다.
- 자리 사용자가 남아 있는 배치도는 삭제할 수 없습니다. 빈 배치도 삭제 시 캐릭터의 해당 위치 연결은 해제됩니다.

## 검증

`npm run test:data`는 메모리 PostgreSQL에서 실제 생성 SQL을 반복 적용하고 자리·상태·위치 권한을 확인합니다. `npm run test:server`는 실제 Next API, `npm run test:browser`는 이동·공간 전환·달력·자리 선택 화면을 확인합니다. 서버·브라우저 검증 전에 `npm run build`를 실행합니다. 자동 테스트는 운영 계정이나 업무 데이터를 사용하지 않습니다.
