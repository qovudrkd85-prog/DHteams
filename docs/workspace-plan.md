# 우리 사무실 구현 계획과 운영 규칙

## 목표와 화면 구성

시작 화면을 팀원들이 함께 꾸미는 작은 사무실로 확장합니다. 상단에는 캐릭터와 가구가 있는 사무실, 그 아래에는 부서 공유 달력, 오른쪽에는 내 출퇴근·팀원 목록·과업 목록을 배치합니다. 모바일에서는 세로로 이어집니다.

1. **회원가입과 내 설정**: 아이디·비밀번호로 가입하고 이름·직책·캐릭터·색상을 설정합니다. 이후 로그인한 계정으로 출퇴근과 일정 등록자를 자동 연결합니다. 상단 내 설정에서 프로필과 비밀번호를 변경합니다.
2. **출근과 퇴근**: 한국 날짜를 기준으로 하루 한 건의 출퇴근 기록을 저장합니다. 출근한 팀원이 배정된 책상에 앉고, 퇴근한 자리에는 빈 의자가 보입니다. 기록의 시각은 서버가 결정합니다.
3. **공간 꾸미기**: 책상·회의 테이블·화분·소파·보드를 추가하고 마우스/터치로 옮깁니다. 키보드로 위치 조절, 회전, 이름 변경, 좌석 배정도 할 수 있습니다. 배치도와 테마를 여러 개 저장해 전환합니다.
4. **함께 쓰는 일정**: 업무/회의/회식/휴가/외근·출장/기타를 선택합니다. 새 일정에는 등록자의 ID·이름·색상이 자동 저장됩니다. 등록자는 담당자·참석자와 별개로 표시하며 전체/내 일정/팀원별 필터를 제공합니다.

## 데이터와 변경 규칙

- `team_members`: Auth 사용자 ID와 연결된 팀원 프로필. 같은 이름이어도 계정별로 구분합니다.
- `team_attendance`: 팀원과 한국 날짜당 한 건. 중복 출근과 중복 퇴근은 기존 기록을 유지합니다. 당일 퇴근 후 재출근은 지원하지 않습니다.
- `office_layouts`: 배치도 이름, 테마, 가구 배열, 변경 시각. 명시적으로 저장하며 다른 팀원의 수정과 충돌하면 덮어쓰지 않습니다.
- `department_events`: 기존 일정에 업무 유형과 등록자 필드를 추가합니다. 이전 일정은 ‘등록자 미지정’으로 남기고, 다른 팀원이 수정해도 처음 등록한 사람은 유지합니다.
- 출퇴근과 일정은 30초마다 갱신하고 창으로 돌아왔을 때 다시 조회합니다. 배치도 편집 중에는 다른 사람의 변경으로 작성 중인 내용을 교체하지 않습니다.
- 계정 로그인 이후 팀 데이터에 접근합니다. 본인 프로필·출퇴근만 변경할 수 있고 일정과 사무실은 공동 수정합니다.

## 설치

1. 부서 일정 테이블이 없는 설치라면 `supabase/schema-department-events.sql`을 먼저 실행합니다.
2. Supabase SQL Editor에서 `supabase/schema-team-workspace.sql` 전체를 실행합니다. 재실행 가능한 추가 마이그레이션입니다.
3. `supabase/schema-accounts.sql`을 마지막으로 적용하고 Supabase Auth의 Confirm Email을 끈 뒤 변경된 앱을 실행하거나 배포합니다.
4. 팀원이 회원가입 후 내 설정을 완료하고, 사무실 꾸미기에서 책상을 배정한 후 저장합니다.
5. 서로 다른 브라우저에서 같은 배치도·팀원·일정이 보이는지 확인합니다.

SQL 실행 전에는 초기 설정 안내를 표시하며 저장되었다고 표시하지 않습니다. 이 저장소에는 DB 관리 접속 정보가 포함되지 않으므로 SQL 적용은 Supabase 관리자 환경에서 진행합니다.

## 검증

- 정적 검사: ESLint, TypeScript, Next.js production build.
- 로컬 브라우저: API를 모의 처리하여 가입/로그인/내 설정/로그아웃, 출퇴근, 캐릭터 표시, 배치 편집/저장/복원, 일정 CRUD/등록자/필터, 오류·충돌·모바일 화면을 확인합니다.
- SQL: 로컬 PGlite에서 마이그레이션 재실행, 데이터 보존, 서버 출퇴근 기록, 등록자 보존과 가구 데이터 제약을 검증합니다.
- 모의 API 검증은 운영 Supabase 연결과 배포 검증을 대신하지 않습니다. 운영 데이터는 테스트에 사용하지 않습니다.
